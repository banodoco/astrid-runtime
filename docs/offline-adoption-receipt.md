# Offline adoption receipt, version 1

`workspace adopt --from OLD --realm-id ID --read-only-source --no-start --data-root OLD-r1 --json --source-manifest PROFILE` creates the absent sibling root and does not start a service. Both flags are required together. The response and `OLD-r1/adopt-receipt.r1.json` contain the same JSON object. A destination that already exists, including one left by an uncertain publication, is never reused or replaced. The installer owns selection, the `update-journal.r1.json` transaction in the new root, and switch-back; Runtime does not write the install record here.

The literal boolean fields `ok`, `source_unchanged`, and `started`, plus `realm_id`, `source`, and `destination`, retain the Agent success contract. `source` and `destination` are absolute realm-root paths. `receipt_version` is 1 and `operation_id` is a fresh random hex identifier. `source_data_root`, `source_root_device`, and `source_root_inode` identify the observed source; `verified_at` is UTC. `source_manifest_sha256` hashes the supplied profile manifest bytes, or the compact, sorted JSON serialization of the resolved profile if no manifest was supplied.

`source_inventory_sha256`, `post_inventory_sha256`, and `destination_inventory_sha256` match on success. The destination digest describes the **private, exact copy before its catalog/profile are rewritten and its copied realm is migrated**, not the final changed R1 tree. Each inventory includes the root and every relative directory and regular file, including SQLite sidecars, support files, and empty directories. Unsupported entry types and ambiguous names refuse the operation. Entries are sorted by UTF-8 path and represented as compact UTF-8 JSON arrays `[relative_path, "dir" or "file", permission_mode, size, mtime_ns, sha256_or_null]`; the root path is the empty string. File hashes are lowercase SHA-256 of bytes. The inventory digest hashes `astrid-full-root-inventory-v1\n` followed by that JSON. The SQLite digest hashes compact JSON of the inventory entries for `.sqlite`, `.sqlite3`, `.db`, and their `-wal`, `-shm`, and `-journal` companions. This is a byte-and-metadata digest, not a SQL query or a logical database checksum; SQLite is never opened on the source.

The inventories detect observed changes, not writes that are completely reversed between observations or changes after the last observation. A receipt is not a health check or launch authorization. The R1 installer must compare its own before/after observations, validate the receipt, and commit selection only after all of its gates pass. Linux exclusive rename and macOS exclusive rename are used for publication; other platforms, including Windows, refuse until qualified.

Runtime inspects an existing supported realm `owner.lock` read-only and nonblocking before copying and before publication; a busy or uninspectable lock refuses adoption. This observation is not writer custody. **LEGACY-R0-OWNERSHIP-EVIDENCE** is an accepted risk: an absent or incompatible legacy ownership mechanism cannot prove the old Runtime is stopped. The installer must independently stop and gate the old owner.

Migration recovery records are bound to the final R1 paths before publication and checked again at the published root. Recovery state and archived bytes remain intact; incomplete provider verification is not marked ready. An interruption after publication can leave a receipt and an uncertain destination, which must not be taken as a successful command or automatically reused.

For a Pinokio R1 selection, the per-user selection must retain legacy `data_root` and `realm_root` as R0 provenance and provide `r1_data_root` and `r1_realm_root` for the active R1. Its `realm_id`, program, Version and service identity must match R1. The program `install.json` must retain the same legacy `data_root` and contain the same active `r1_data_root`. Invalid or missing R1 fields refuse binding without falling back to R0. Runtime requires these fields for R1 stop binding; it does not write them. The Agent must coordinate both records, stop the exact R1 owner and validate stop evidence before restoring the saved R0 service and selection, and handle interruptions and divergent histories while retaining both roots.
